# 学生档案与分层长期记忆：L0—L3 数据形态设计

版本：v2.2（题目难度等级接入）  
日期：2026-11-02  
范围：只定义**提取与存储**（何时提取、存成什么、怎么校验），不含读取应用、画像编辑页、前端展示。L4 不在本次范围。

本文取代 v1.0 版本，是 `docs/数据库设计.md`「2026-10-28：学生画像与长期记忆存储」的细化规格。产品口径以 `docs/需求文档.md` 为准。

## 1. 四层职责（v2 定义）

| 层 | 职责 | 介质 | 写入者 |
| --- | --- | --- | --- |
| L0 | 学生基本信息，长期不变 | MySQL `student_profile_l0` | 学生接口 |
| L1 | 对 L2 的提取（检索索引） | Redis String | 由 L2 确定性投影 |
| L2 | 按标准化知识点大类聚合的掌握画像 | Redis String | 提取任务 |
| L3 | 对话原文 | Redis String | 提取任务（仅追加） |

与 v1 的关键变化：
- **L0 不再存薄弱点候选（observations）**，只保留长期不变的基本信息。
- **L2 从"月度对话摘要"改为"按知识点大类聚合的掌握画像"**：每个大类下记录核心知识点、核心数学能力点、掌握现状（四档）、时间、题号。
- **掌握现状只看学生自己作答**；教师示范、看答案、辅导完成不判定掌握程度。

## 2. 标准化分类体系（本次定稿）

### 2.1 知识点大类（9 类，编码稳定不可变）

| 编码 | 名称 |
| --- | --- |
| ALG | 代数与方程 |
| FUNC | 函数与图象 |
| SEQ | 数列 |
| TRIG | 三角函数 |
| VEC | 平面向量 |
| SOLID | 立体几何 |
| ANALYTIC | 解析几何 |
| PROB | 概率与统计 |
| CALC | 导数与微积分 |

### 2.2 数学能力维度（5 类）

| 编码 | 名称 |
| --- | --- |
| AB-COMPUTE | 运算求解 |
| AB-REASON | 逻辑推理 |
| AB-MODEL | 数学建模 |
| AB-SPACE | 直观想象 |
| AB-DATA | 数据分析 |

规则：
- 大类编码固定、只增不改。子知识点（`topic`）允许新增，挂在类下。
- 模型提取只能从已注册的分类中选择，服务端校验 `area` 与 `ability` 编码必须在白名单内，未注册的编码整批拒收，杜绝模型杜撰分类。
- 分类白名单存于 `agent-design/contracts/knowledge_taxonomy.json`，与提取 prompt 同源，避免代码里写死两套。

## 3. 标识、路径与版本

- `student_id`：`^[A-Za-z0-9][A-Za-z0-9_-]{0,127}$`，只来自服务端身份。
- `month`：`YYYY-MM`，由原始学生输入时间转北京时间确定。
- 路径：

| 层 | 路径 |
| --- | --- |
| L1 | `/user/memory/indexes/{student_id}/{YYYY-MM}.md` |
| L2 | `/user/memory/{student_id}/{YYYY-MM}/meta.md` |
| L3 | `/user/memory/{student_id}/{YYYY-MM}/content.md` |

- `revision`：同月三层共用，每次发布 +1；Lua 比较旧值后原子 SET。
- `schema_version`：本次升到 `2`。读取兼容 `1`（缺失字段取零值并标记 legacy），写入只允许 `2`。
- 无 TTL。`agent_message` 始终是原始事实。

## 4. L0 · MySQL `student_profile_l0`

表结构（v2 删除 `observations_json` 列）：

```sql
student_profile_l0(
  id BIGINT UNSIGNED PK AUTO_INCREMENT,
  student_id VARCHAR(128) UNIQUE,      -- ascii_bin
  revision BIGINT UNSIGNED,            -- 乐观锁
  basic_json JSON NOT NULL,
  updated_at DATETIME(6) NOT NULL
)
```

`basic_json`（只由学生接口写，长期不变）：

```json
{
  "name": "小林",
  "grade": "高一",
  "learning_goals": ["期中考 85 分"],
  "explanation_preference": "先提示思路，再给完整步骤",
  "updated_at": "2026-10-30T08:00:00Z"
}
```

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `name` | string | ≤50 字 |
| `grade` | string | ≤30 字 |
| `learning_goals` | string[] | ≤10 项，每项 ≤100 字 |
| `explanation_preference` | string | ≤300 字 |
| `updated_at` | RFC3339 | 最近保存时间 |

**v2 移除**：`weak_subjects` / `weak_knowledge_points` / `weak_abilities`（薄弱自述挪到 L2 的掌握画像里承载，L0 只留身份类信息）。旧字段读取兼容（忽略），新写入不再产生。

**v2 移除 `observations_json` 列**：L0 不再存模型薄弱点候选。迁移脚本删除该列，先备份旧值到 `_archive`，不自动导入新结构。

## 5. L2 · Redis `{student_id}/{YYYY-MM}/meta.md`（掌握画像）

```yaml
schema_version: 2
layer: L2
student_id: local-pilot
month: 2026-10
revision: 12
updated_at: 2026-10-30T08:00:00Z
next_paths:
  - /user/memory/local-pilot/2026-10/content.md
content:
  summary: 本月主练二次函数与数列；学生能独立完成一元一次方程，闭区间最值端点比较反复出错。
  knowledge_areas:
    - area: FUNC
      topics:
        - topic: 二次函数闭区间最值
          mastery: partial
          ability: AB-COMPUTE
          error_count: 3
          stability: 0.35
          difficulty: 0.44
          last_seen: 2026-10-28T02:55:00Z
          question_ids:
            - q_01a17c6c811674c082225bfd360d48d4
        - topic: 二次函数配方法
          mastery: mastered
          ability: AB-COMPUTE
          error_count: 0
          stability: 0.80
          difficulty: 0.20
          last_seen: 2026-10-27T02:55:00Z
          question_ids:
            - q_01a17cc8b6e77a6f89c08cff7695d1f4
    - area: SEQ
      topics:
        - topic: 等差数列求和
          mastery: familiar
          ability: AB-REASON
          error_count: 1
          stability: 0.40
          difficulty: 0.28
          last_seen: 2026-10-28T02:55:00Z
          question_ids:
            - q_01a17cf63de371b69ee6eec4ae32dccf
  turn_count: 24
  span:
    first: 2026-10-08
    last: 2026-10-30
```

### 5.1 字段说明

| 字段 | 约束 |
| --- | --- |
| `summary` | 1—2000 字，状态视角总结（练了什么、能做什么、卡在哪） |
| `knowledge_areas` | ≤9 项，`area` 必须是已注册大类编码 |
| `topics` | 每个 area ≤50 项；`topic` ≤60 字 |
| `mastery` | 四档之一（见 5.2） |
| `ability` | 5 个能力编码之一 |
| `error_count` | 该 topic 当月累计犯错次数（≥0），只统计学生自己作答且答错的轮次，答对（mastered）归零 |
| `stability` | 记忆稳定性 `s ∈ [0,1]`，越大衰减越慢；服务端随 mastery 档位增减（详见 5.4），旧文档缺失取中性先验 0.5 |
| `difficulty` | 知识点难度 `d ∈ [0,1]`，由 `error_count` 确定性推导（`0.2 + 0.08 × error_count`），封顶 1.0 |
| `last_seen` | 该 topic 最近一次有证据作答的时间 |
| `question_ids` | ≤50 个 `question_id`，为该 topic 的证据题号，升序去重 |
| `turn_count` / `span` | 由合并后的 L3 计算 |

### 5.2 掌握程度四档

| 档位 | 编码 | 判定依据（只看学生作答） |
| --- | --- | --- |
| 未接触 | `unseen` | 本月只出现教师示范 / 看答案，学生无独立作答证据 |
| 已了解 | `familiar` | 学生作答但未形成完整正确解，或仅复述/提问 |
| 基本掌握 | `partial` | 学生答对但有错误、遗漏或需要提示 |
| 熟练掌握 | `mastered` | 学生独立完整答对 |

**判定规则（服务端确定性，模型只产出候选证据）：**
1. 只有学生自己作答的轮次才更新 `mastery`；教师示范、看答案轮次只计入 `unseen`，不改变已有档位。
2. 同 topic 多次作答：档位取**最高**档（`unseen < familiar < partial < mastered`），学生后来自主答对可提升档位，不因一次示范降档。
3. 模型输出的是"作答事实 + 建议档位 + 本轮是否犯错（`incorrect`）"，服务端按上述规则裁定最终档位，不直接信任模型给的档位。
4. 无法判定时置 `unseen`，不杜撰"已掌握"。

### 5.3 聚合与容量

- 聚合轴 = (`area`, `topic`)：同 topic 的多次问答合并证据（`question_ids` 并集、`last_seen` 取最大、`mastery` 取最高）。
- **犯错次数累计（答对即清零）**：同 topic 每出现一次"学生自己作答且答错"（`incorrect=true`）的轮次，`error_count` 累加 1；一旦学生独立完整答对（`mastered`），`error_count` 立即归零。教师示范、看答案、答对均不累加。累计与归零逻辑由服务端完成，模型只标记本轮是否错、不输出累计数值。
- **口径约束**：`mastered` 时 `incorrect` 必须为 `false`（完整答对无错）；`partial`（答对但有错误遗漏）时 `incorrect` 必须为 `true`；`familiar` 按是否确有错误判 `true/false`。服务端对矛盾输入（`mastered` + `incorrect=true`）强制规范化 `incorrect=false`，不信任模型。
- **每月独立**：`error_count` 与 `mastery` 只统计当月，跨月不延续、月初归零；跨月画像由 L1 索引逐月下钻呈现。
- 单文档 ≤8 MB；`topics` 总数超限时拒绝发布并报 `MONTH_CAPACITY_EXCEEDED`，不静默截断。
- `teaching_action`（教师示范）**不入 `topics`**，只反映在 `summary` 与"未接触"档位上。

### 5.4 遗忘维度（HLR 简化模型）

> 详见 `docs/学生档案遗忘维度设计.md`。`mastery` 是离散的"能力档位"（只看最近作答质量），遗忘是连续的"时间维度"（随时间衰减），二者正交，组合出「当前掌握度」。

**稳定性更新**（服务端确定性，模型不产出、不篡改）：

| 本次作答 | `stability` 变化 |
| --- | --- |
| `mastered`（独立完整答对） | `+0.15` |
| `partial`（答对但有错） | `+0.05` |
| `familiar`（未形成完整解） | `−0.10` |
| `unseen`（示范/看答案） | 不变 |

初值 `0.5`，`clamp` 到 [0,1]。

**难度推导**：`difficulty = clamp(0.2 + 0.08 × error_count, 0, 1)`，随犯错次数单调上升，`error_count` 归零时难度回落至 0.2。

**可回忆概率（读取侧派生，不落盘）**：`retrievability = 0.5^(elapsed / half_life)`，其中 `elapsed = now − last_seen`（天），`half_life = 1 + 14 × stability × (1 − difficulty)`（天）。读取 L2 时由 `read_student_memory` 工具按当前时间折算 `retrievability` 与 `due`（`retrievability < 0.80`）注入上下文，**不写回源文档**，保持 L2 时间无关、可复算。

**旧数据兜底**：v2 早期文档无 `stability`/`difficulty` 字段，反序列化得零值；`BuildMonth` 与读取侧均对零值回填中性先验（`0.5`/`0.2`），避免折算退化。

### 5.5 提取器输入：题目元数据 + 历史聚合（与对话原文分离）

`Extract` 的输入不再是「只有对话原文」，而是**三段分离背景**，让掌握判断同时参考题目本身难度与近期作答历史，但保持「只依据学生实际作答」的边界：

| 输入段 | 来源 | 内容 | 边界 |
| --- | --- | --- | --- |
| `sources`（对话原文） | L3 待处理轮次 | 学生 user + 助手 assistant + 题干 | **判定依据** |
| `question_meta` | solve 模块 `Question.Difficulty` + `Solution.KnowledgePoints` 映射 | `question_id` / `knowledge_tags`（映射后的 taxonomy 编码）/ `difficulty`（easy/medium/hard）/ `is_variant` | 难度校准背景，**绝不含答案/解析/标准解法** |
| `recent_topics` | 复用 L2 已裁定锚点 | `area` / `topic` / `error_count` / `last_seen` / `stability` / `mastery` | 近期犯错背景，**不重新聚合、不新增存储** |

关键设计：

1. **编码映射**：solve 模块用独立的知识点 Catalog（`sets_logic`、`functions_derivatives` 等 8 类），与记忆 Taxonomy（`ALG`、`FUNC` 等 9 类）不是同一套。`MapSolveKnowledge` 纯函数做确定性映射，**未知编码返回空并丢弃、绝不猜测**。当前映射（`catalogmap.go`）：`sets_logic`/`equations_inequalities`→`ALG`，`functions_derivatives`→`FUNC`，`sequences`→`SEQ`，`trigonometry`→`TRIG`，`analytic_geometry`→`ANALYTIC`，`solid_geometry`→`SOLID`，`probability_statistics`→`PROB`（`CALC`、`VEC` 暂无 solve 侧来源）。

2. **数据通路**：记忆仓库 `pending()` 已通过 `LEFT JOIN teaching_solution_receipt.view_json` 拿到 solve 的 `View`，把 `Solution.KnowledgePoints` 经映射表转成 taxonomy 编码，填入 `OriginalTurn.KnowledgeTags`（答案、解析、步骤一律不进记忆）。`questionContext()` 再把 `KnowledgeTags`/`Difficulty` 装进 `QuestionMeta`，把旧 L2 的 topic 装进 `RecentTopics`，一并传给 `Extract`。

3. **难度等级**：题目客观难度为三档 `easy` / `medium` / `hard`，是 `solve.Question.Difficulty` 的必填枚举字段（解题时由模型按题目本身计算量/概念深度/综合程度标注，与学生是否答对无关）。`pending()` 把它透传到 `OriginalTurn.Difficulty`，再由 `questionContext()` 装入 `QuestionMeta.Difficulty`，供提取器做难度校准。校验在 `solve.Validate` 拦截非法档位。

4. **prompt 约束**：`question_meta` / `recent_topics` 只用于「判断这道题本身有多难」和「该知识点近期是否连续出错」，**不能替代对 student 实际作答的观察，更不能据此直接判定掌握档位**。

## 6. L1 · Redis `indexes/{student_id}/{YYYY-MM}.md`（对 L2 的提取）

```yaml
schema_version: 2

month: 2026-10
revision: 12
updated_at: 2026-10-30T08:00:00Z
next_paths:
  - /user/memory/local-pilot/2026-10/meta.md
content:
  keywords:
    - FUNC:二次函数闭区间最值
    - FUNC:二次函数配方法

  span:

    last: 2026-10-30
```

| 字段 | 来源（全部确定性投影自同 revision 的 L2） |
| --- | --- |
| `keywords` | 每个 topic 一条 `"{area}:{topic}"`，按 (`area`, `topic`) 升序 |
| `turn_count` | 复制 `L2.content.turn_count` |
| `span` | 复制 `L2.content.span` |

约束：
- **L1 只由 L2 投影**，`IndexFromSummary` 结构相等校验，不直接引用 L3。

- `keywords` 为空（该月无任何作答）时**不发布该月索引**。

## 7. L3 · Redis `{student_id}/{YYYY-MM}/content.md`（对话原文）

```yaml
schema_version: 2
layer: L3
student_id: local-pilot
month: 2026-10
revision: 12
updated_at: 2026-10-30T08:00:00Z
next_paths: []
content:
  turns:
    - source:
        conversation_id: c_01a17c6697f879a6916c0278aef243c6
        branch_id: b_01a17c6697f879a7b8a6b0be01d779cc
        turn_id: t_01a17c66984276188ab3eef86fffc60d
        message_ids:
          - mu_01a17c66984276188ab3eef86fffc60d
          - ma_01a17c66984276188ab3eef86fffc60d
        question_id: q_01a17c6c811674c082225bfd360d48d4
      seq: 24
      input_type: text
      user: 我在闭区间最值这块总错，能不能讲讲端点怎么比较？
      assistant: 先看对称轴是否落在区间内……
      question_text: 求 f(x)=x²−4x+3 在 [0,3] 上的最值
      image_asset_id: ""
      created_at: 2026-10-28T02:55:00Z
```

字段与约束同 v1：只追加（append-only）、`seq` 连续（按**追加顺序**编号，非时间顺序）、`source` 唯一、单月 ≤8 MB、分页 `offset/limit(1—10)`。新一批 turn 即使 `created_at` 早于已有 turn（空闲补录、时钟回拨）也只追加到末尾，不重排历史；`span.first/last` 独立按真实时间取全局最小/最大，与追加顺序无关。

## 8. 写入时序（不变）

1. `Discover` → 登记 SEALED 轮次指针，建 state 行。
2. `Due`（第 9 节）→ `Claim` 加租约，取 ≤10 条待处理轮次。
3. 按月分组、`Load` 旧文档、按 `SourceID` 去重。
4. `Extract`（模型）：只输出作答事实 + 建议档位 + 涉及 topic/ability，不直接给最终档位。输入为**分离的三段背景**（见 5.5）：对话原文（判定依据）+ 题目元数据（难度校准背景）+ 历史聚合（近期犯错背景），后两者绝不含答案、解析、标准解法，模型掌握判断仍只看学生实际作答。
5. `BuildMonth`：校验分类白名单 → 服务端裁定 `mastery` 与累加 `error_count` → 联动更新 `stability`/`difficulty`（见 5.4）→ 按 (`area`,`topic`) 聚合 → 合并 L3（旧历史保持原序、新批次按时间排序后追加，重排连续 `seq`）→ 计算 `turn_count/span` → 投影 L1。
6. `Publish`：Lua 原子写三份。
7. `Complete`：MySQL 事务标记 `processed_at`、清租约（L0 已无 observations 可合并）。
8. 失败：`Retry` 写 `next_attempt_at = now + 1min` + 稳定错误码。

## 9. 三个触发时机

| 时机 | 判定式 |
| --- | --- |
| `ten_turns` | `pending >= 10` |
| `new_conversation` | `pending > 0` 且 `max(pending 所属 conversation.id) < max(active conversation.id)` |
| `idle_two_hours` | `pending > 0` 且 `now >= last_user_input_at + 2h` |

优先级 `new_conversation` > `ten_turns` > `idle_two_hours`。计数口径：一轮 = 同 `turn_id` 的 user + assistant 均 SEALED。空会话不触发、不调模型。成功轮次与新建会话 `Notify`，15 秒轮询兜底。

## 10. 不变量清单

1. `L1 == f(L2)`，结构相等，不等拒绝发布。
2. `revision` 三层一致且 = 旧值 +1。
3. L3 前缀不变、`seq` 连续、`source` 唯一。
4. `area` / `ability` 编码必须在白名单内。
5. `mastery` 由服务端按规则裁定，档位 ∈ 四档。
6. 每个 topic 的 `question_ids` 能在同月 L3 找到对应 `question_id`。
7. `keywords` 非空才发布。
8. 学生 A 路径不能被学生 B 读出（精确匹配）。
9. `stability` / `difficulty` 均 ∈ [0,1]，零值旧数据在 `BuildMonth` 与读取侧回填中性先验。

11. 提取器输入的 `question_meta` / `recent_topics` **绝不包含答案、解析、标准解法**；题目知识点编码经映射表转换，未知编码丢弃、不猜测。

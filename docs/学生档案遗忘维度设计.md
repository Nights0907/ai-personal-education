# 学生档案遗忘维度设计

> 版本：v1.0 ｜ 日期：2026-11-02 ｜ 关联：`docs/AI教育长期记忆文献综述.md` 建议 1
> 状态：设计稿（待评审），尚未实现
> 目标：给 L2 的 `Topic` 引入「遗忘」维度，让 `mastery`/`error_count` 从「静态快照」升级为「随时间衰减的掌握度」，并输出「下次复习时机」预测。

---

## 1. 为什么需要遗忘维度

当前 `Topic` 只有 `mastery`（四档）与 `error_count`，二者是**时间无关**的静态值：一个知识点 3 个月前 `mastered`，和 3 天前 `mastered`，在数据里长得完全一样。这与文献两条主线共同强调的「记忆随时间指数衰减」直接冲突：

- 主线一（遗忘曲线）：不复习的记忆会衰减，`mastered` 不等于「现在还记得」。
- 主线二（KT）：`MemoryKT`/`LefoKT` 证明，显式建模遗忘显著提升掌握度估计准确性。

**结论**：`mastery` 应表示「最近一次有效作答时的掌握档位」，而「当前掌握度」必须结合**距上次作答的时长**动态折算。

---

## 2. 模型选型：HLR 而非完整 FSRS

在 FSRS 与 HLR 之间，**选 HLR（半衰期回归）的简化形式**，理由如下：

| 维度 | FSRS v5 | HLR（简化） |
|---|---|---|
| 依赖数据 | 需大量复习序列拟合神经网络参数 | 每条目 3 个参数，可解析计算 |
| 冷启动 | 差（需历史） | 好（有先验默认值） |
| 输入信号 | 明确的「对/错」复习记录 | 只需 `mastery` 档位 + 时间戳 |
| 与本项目契合 | 本项目是「单题作答」而非「闪卡复习」，无「难度 rating」闭环 | 可直接复用现有 `mastery`/`authored` 语义 |
| 可解释性 | 黑盒 | 半衰期有直观含义 |

本项目当前是**月度归档、单题作答、服务端裁定**，没有 FSRS 所需的连续复习打分闭环；HLR 的「每个知识点一个半衰期」模型足够、可解释、且能无缝嵌入现有 `BuildMonth`。**FSRS 留作后续（若上线「复习推送」闭环再引入）**。

---

## 3. 字段设计

在 `Topic` 结构上新增 3 个字段（均为**服务端确定性计算**，模型不产出、不篡改）：

```yaml
topic: 二次函数闭区间最值
mastery: partial              # 最近一次有效作答的档位（现有字段，语义不变）
error_count: 2                # 现有字段
last_seen: 2026-10-28T02:55:00Z   # 现有字段：最近一次有效作答时间
stability: 0.62               # 新增：记忆稳定性 s ∈ [0,1]
difficulty: 0.71              # 新增：知识点难度 d ∈ [0,1]
retrievability: 0.35          # 新增：当前可回忆概率 R，读取时按 elapsed 动态折算
```

| 字段 | 类型 | 含义 | 计算方 |
|---|---|---|---|
| `stability` | float ∈ [0,1] | 记忆稳定性，越大衰减越慢 | 服务端，随答对提升、答错下降 |
| `difficulty` | float ∈ [0,1] | 知识点固有难度，越大越难记 | 服务端，随犯错次数缓慢上升 |
| `retrievability` | float ∈ [0,1] | **当前**可回忆概率 | 服务端，`f(stability, elapsed)` 动态折算，不落盘或落盘时按读取时刻刷新 |

> 设计取舍：`retrievability` 是**时间函数**，不应在写入时冻结成静态值，否则又退回「静态快照」。方案是：**写入时只存 `stability`/`difficulty`，读取时（或渲染给模型时）用 `elapsed = now - last_seen` 实时折算 `retrievability`**。若必须落盘（如前端展示），由读取侧工具计算后返回，不写回源文档。

## 4. 公式

### 4.1 稳定性更新（HLR 核心）

沿用 HLR 思想，把「答对/答错」映射为稳定性的增减：

```
stability' = clamp(
    stability + Δ,
    0.0, 1.0
)

Δ 由本次作答结果决定：
  mastered   → Δ = +0.15           # 独立完整答对，记忆加固
  partial    → Δ = +0.05           # 答对但有错，小幅加固
  familiar   → Δ = -0.10           # 未形成完整解，弱化
  unseen     → Δ = 0               # 示范/看答案，不改变
```

`clamp` 到 [0,1]，初值 `stability = 0.5`（新知识点中性先验，对应冷启动）。

### 4.2 难度更新

难度随「犯错次数」单调缓慢上升，模拟「越难的知识点遗忘越快、越需要复习」：

```
difficulty' = clamp( 0.2 + 0.08 × error_count , 0.0, 1.0 )
```

初值 0.2；`error_count` 每次答错 +1（现有逻辑），答对清零（现有「答对即清零」规则），难度随之回落。

### 4.3 可回忆概率（读取时折算）

用指数衰减（Ebbinghaus 形式），半衰期由 `stability` 与 `difficulty` 共同决定：

```
elapsed = now - last_seen          # 单位：天
half_life = 1 + 14 × stability × (1 - difficulty)   # 半衰期：天
retrievability = 0.5 ^ (elapsed / half_life)
```

- `stability` 越高、`difficulty` 越低 → 半衰期越长 → 遗忘越慢。
- 半衰期下限 1 天（`+1` 保证即使 `stability=0` 也有意义），`stability=1, difficulty=0` 时半衰期 = 15 天。
- `retrievability` 从 1.0（刚作答）指数衰减向 0。

### 4.4 下次复习时机

当 `retrievability` 跌破阈值 `τ = 0.80` 时，该知识点进入「待复习」状态，作为引导式教学 / 复习推送的候选：

```
due = (retrievability < 0.80)
```

阈值 0.80 对齐主流间隔重复的「目标保持率」设定（SuperMemo/Anki 常取 0.80–0.90），可配置。

## 5. mastery 与遗忘的协同

关键原则：**`mastery` 是「能力档位」（离散、只看最近作答质量），遗忘是「时间维度」（连续、随时间衰减）。二者正交，但组合出「当前掌握度」**。

| 场景 | `mastery`（能力） | `retrievability`（记忆） | 教学含义 |
|---|---|---|---|
| 刚答对 | `mastered` | 高（~1.0） | 已掌握且记得，无需干预 |
| 答对已久 | `mastered` | 低（< 0.80） | 会做但可能忘了 → 触发复习 |
| 最近答错 | `partial` | 高 | 刚学过还错 → 继续讲解 |
| 久未接触 | `familiar` | 低 | 陌生又记不清 → 从概念讲起 |

**协同规则（写入 `BuildMonth` / 读取侧）：**

1. `mastery` 的裁定逻辑**不变**（最高档胜出、示范不算、答对即清零 `error_count`）——遗忘维度不改变能力档位的判定。
2. `stability`/`difficulty` 随 `mastery` 裁决结果**联动更新**（见 4.1/4.2），与 `mastery` 同步写入。
3. `retrievability` **只在读取时折算**，绝不写回 `Topic`（保持 L2 源文档时间无关、可复算）。
4. 读取侧（`read_student_memory` 工具 / 前端展示）注入上下文时，把 `retrievability` 与 `due` 作为派生字段附在 topic 上，供引导式教学判断「该复习还是该讲解」。

## 7. 待评审决策点

1. **阈值 τ=0.80 是否合适**：偏保守（复习更频繁）还是放宽到 0.70？
2. **稳定性步长（±0.15/0.05/0.10）是否合理**：是否需要区分「连续答对加速加固」？
3. **`retrievability` 落盘与否**：本方案主张「读取侧派生、不落盘」，团队是否接受前端需要多一次换算？
4. **难度初值 0.2、步长 0.08**：是否要与 `error_count` 的「答对即清零」语义完全联动（答对后难度回落）？

## 附：与「每月独立」的关系

本项目已定稿「`error_count`/`mastery` 每月独立、月初归零」。遗忘维度**同样按月独立**：`stability`/`difficulty` 在每月新文档中从初值重新开始，`last_seen` 也重置为当月时间。跨月连续性仍靠 L1 索引逐月下钻，与现有「每月独立」决策一致，不引入跨月结转。
